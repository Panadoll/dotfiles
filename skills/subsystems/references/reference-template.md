# 子系统参考页模板

复制下面分隔线之后的内容到 `docs/subsystems/<name>.md`，删掉不适用的可选小节和所有尖括号占位。用于检查的格式约定：

- 源码链接写成相对于本页的路径：``[`store.py`](../../core/store.py)``。
- 把符号绑定到文件，脚本才能检查它是否还在：``[`Storage`](../../core/storage.py)``、`` `save_item` in [`storage.py`](../../core/storage.py) ``，或者 ``[`storage.py`](../../core/storage.py) `Storage` ``。
- 事实源表格优先点名稳定的公开符号（类、公开函数、表名）。运行时路径可以点名私有函数，但它们一改名文档就得跟着改，只点名读者确实需要跳转过去的那几个。
- 每段结尾可以写一行 `实现：` 和一行 `验证：`。`验证：` 后面只放测试名、测试文件或完整命令，命令用反引号包住。
- 页首的 `verified-at: X` 表示以提交 X 为基线核对过本页引用的源码，不等于行为已被测试证明；验证状态记在“验证”小节。init 和 audit 在完成源码复核、记录“暂无”或“需要外部条件”的范围和原因后，可以写入或刷新；命令失败时不写、不刷新。

写多少由内容决定。一个两三条规则的子系统写半页就够；复杂的子系统可以分多个二级标题，每个标题自带实现和验证行。
