# Subsystem 架构设计参考标准模板 (Subsystem Design Reference)

> **定位**：这是系统的“压缩世界模型（Compressed World Model）”。不追求罗列每一个内部函数，而是描述跨模块/跨包组件共同构成的外部契约、运行时路径、事实源与故障边界。

## 1. 职责划分与唯一事实源 (Responsibilities & Sources of Truth)

> **原则**：单一事实源。每个职责或状态必须有明确的代码归属。Agent 顺着符号跳转源码，禁止在代码库中盲目漫游猜解。

| 组件 / 职责 | 核心责任 | 源码唯一事实源 (Source File & Symbol) |
| :--- | :--- | :--- |
| **入口 / 适配层** | 参数解析、协议适配、请求校验与上下文提取 | [`path/to/entry.ts`](#) -> `handleRequest` |
| **状态持有 (Store)** | 会话生命周期、本地配置读写、内存/持久化存储 | [`path/to/store.go`](#) -> `StateStore` |
| **核心业务逻辑** | 编排调度、状态机流转、核心算法计算 | [`path/to/engine.rs`](#) -> `CoreEngine` |
| **边界 / 外部通信** | 第三方 API 通信、RPC 调用、下游系统适配 | [`path/to/client.py`](#) -> `ExternalClient` |

## 2. 运行时主调用链路 (Runtime Path)

> **原则**：用带编号的时序步序，清晰描述一次典型触发到产生最终副作用的全过程。

1. **入口接收入口与校验**：调用方发起请求，入口层完成鉴权与基本参数合法性检验。
2. **状态装载与上下文建立**：从 Store 载入当前依赖的状态切片；若状态不存在，依据默认策略初始化或阻断。
3. **数据转换与核心流转**：将外部请求转换为系统内部规范表达（Internal Representation），驱动核心引擎执行。
4. **副作用发生与持久化**：将变更状态回写至持久化存储，触发必要的消息广播或事件通知。
5. **响应返回与清理**：向调用方返回结构化结果，释放临时资源（如连接句柄、缓存锁）。

## 3. 状态管理与漂移恢复 (State & Drift Handling)

* **状态分层**：
  * **瞬时运行状态 (Runtime State)**：内存中的连接对象、执行上下文、临时缓存。
  * **持久持久状态 (Durable State)**：数据库记录、磁盘配置文件、事务日志。
* **漂移防范与自愈策略 (Drift Reconciliation)**：
  * 当进程异常重启、并发写入或网络分区导致内存与持久化不一致时，系统如何自愈？
  * （例：启动时重放未决日志、周期性对账轮询、乐观锁版本校验）。

## 4. 硬性约束与降级行为 (Invariants & Failure Behavior)

* **核心不变量 (Invariants - 任何改动严禁破坏)**：
  * [例：同一资源在任意时刻全局只能有一个写事务持有锁]
  * [例：对外暴露的 ID 必须全局唯一且不可变]
* **超时与资源限制**：执行超时阈值、最大并发限制、重试次数上限。
* **故障行为与降级策略**：
  * **Fail-Open 还是 Fail-Closed**？发生故障时是阻断流程，还是记录日志后放行并采用降级兜底？
  * **调用方体感 (Caller/Model Experience)**：异常时调用方或 AI 模型会接收到什么结构化错误或提示？
