# Agent Note 模板

格式来自 DeepSeek Harness 的 `.agents/notes/`，做了简化。

## 什么时候写

只在三个条件都成立时写：

1. 这个决定会长期影响代码；
2. 理由在代码、测试和现有文档里都看不出来；
3. 以后有人可能想“简化”或“优化”掉它。

机械改动、局部 UI 调整、一次性修复不需要写。已有 Note 管这个决定时，更新那一条。

## 放在哪

默认放在 `docs/agent-notes/<状态>/<yyyy-mm-dd>-<主题>.md`。日期取这个话题第一次提出的那天。仓库已有同类目录（例如 `.agents/notes/`、`docs/adr/`）时沿用已有目录。

- `proposed/`：提议中，还没实现或只实现了一部分；
- `implemented/`：已经上线。之后文件挪了、包改名了、默认值变了，在同一个改动里更新 Note 里的这些事实，但决定本身不改；
- `rejected/`：考虑过但否决了。只在它能阻止一个看起来合理的错误时保留。

决定变了，就写一条新 Note 取代旧的，两条互相链接，不要把旧 Note 改成相反的结论。

## 格式

```markdown
# Agent Note: <标题>

Status: <proposed | implemented | rejected — 一句话否决理由>

## 问题

<为什么需要做决定。不看方案也能读懂。>

## 决定

<选了什么，边界在哪。implemented 状态用现在时描述已经上线的事实，不写“应该”。>

## 考虑过的其他方案

- **<方案>**：<好处>，<为什么没选>。

## 后果

- <得到了什么，放弃了什么。>
- <什么条件下值得重新考虑。>

## 验证

<哪些测试或检查守住这个决定；没有就写明缺口。>
```

## 示例：放弃直觉做法的那一类

> 代码里有一层 A → B → C，Agent 会想：为什么不直接 A → C？代码只能说明 B 存在，说明不了“试过 A → C，结果会在重放和持久化时丢状态，所以才有 B”。这句话就是 Note 的“考虑过的其他方案”和“后果”要写的内容。
